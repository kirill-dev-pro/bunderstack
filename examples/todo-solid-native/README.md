# todo-solid-native

The same distributed todo as `todo-solid-2`, with the client data layer
reduced to almost nothing: no TanStack Query, no oRPC client, no hand-written
API surface. The browser talks to Bunderstack's live-view stream and REST
endpoints directly, using Solid 2.0 primitives only.

- **`src/api.gen.ts`** — generated by `bun scripts/generate-api.ts` from the
  app's `/api/openapi.json` (`bunderstack/codegen`). Zero-runtime: typed
  functions over `fetch`, plus an inlined SSE parser for live views. Own the
  file like any other source.
- **`src/native/todos.ts`** — one projection store whose derive function is a
  single infinite async iterator over `GET /api/todos/live`: a snapshot frame,
  then server-decided upsert/remove frames forever. Reconnecting restarts the
  stream and its snapshot *is* the recovery — no event buffers, no
  Last-Event-ID bookkeeping, no local filter evaluation.
- **`TodoList.tsx`** — linear `action` generators (`affects` + optimistic
  draft + `yield fetch`). Unsettled reads fall into `<Loading>`, rejections
  into `<Errored>`; failed mutations surface through one global
  `unhandledrejection` listener that also resyncs server truth.

Backend side of the experiment (branch `feat/solid-native-backend`):

- `GET /api/{table}/live` — live views: snapshot + server-filtered deltas.
- Membership against `filters` is decided per record on the server
  (`src/api/live-view.ts`), so clients patch without knowing filter/sort
  rules.

Run:

```sh
bun run dev
```

Open two windows side by side and watch writes propagate.
